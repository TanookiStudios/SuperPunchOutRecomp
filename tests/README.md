# tests/

Everything here runs headless (no window, no sound, your real saves are never touched) and is repeatable:
the emulation is deterministic and every run starts from a fresh, empty save.

## Build
| File | What it is |
|---|---|
| `build_game.sh` | Builds the game into `build-game/` (original scaffold CMakeLists + our cheats file + `spo_stats.c`). Run it after every `tools/regen.sh`. |
| `extras_build.cmake`, `spo_stats.c` | Adds `src/superpunchout_extras.c` and a test-only counter to that build. Not part of the shipped game. |

## Routes (input scripts the game host reads; each starts from power-on)
Generated by `python3 tests/gen_routes.py` (edit the pieces there, not the text files).
| Route | What it does |
|---|---|
| `route_attract.txt` | 6000 frames, no input: intro, title, the "How to win" demo fights. |
| `route_fight_gabby.txt` | Title, name "A", Championship, Minor circuit, first fight (Gabby Jay), then punches and dodges to frame 6000. Mac gets hurt and goes down, so does Gabby. |
| `route_win_next.txt` | Same fight, but the boxer's health is set to 1 before each round of punches so he is knocked out: results, records screen, second boxer's card (Bear Hugger), second fight. |
| `route_lose.txt` | Mac's health held at 1, no input: Gabby knocks him out, results, retry, repeated until tries run out: GAME OVER, title, menu, Continue, mode and circuit select. |
| `route_menus.txt` | Mode select and the Button Setting screen. |
| `route_circuit_minor/major/world/special.txt` | Cheat switches on (skip every fight, start at boxer 1 of that circuit): all four boxers' cards and fights, then the circuit-clear screens (Special ends in the credits). Sets `SPO_CHEATS` through the `#@ netenv=` header line. |
| `route_cheat_*.txt`, `gen_routes_cheats.py` | Proof routes for the cheats. `python3 tests/gen_routes_cheats.py --run` runs every proof (about 11 minutes) and prints PASS/FAIL; the inertness proofs need a build from before the cheats in `ref/SuperPunchOutRecomp` (or `REF_BIN=`). |

## Running
| File | What it does |
|---|---|
| `run_route.sh <route> [native\|interp] [outdir]` | Runs one route. Saves screenshots/state at each `dump` line and a hash of all game RAM after every frame. `COVERAGE=1` also records what the interpreter ran. |
| `coverage_check.sh`, `coverage_iterate.sh` | One round of the "make more of it native" loop: run routes with coverage, promote what was found, regenerate, rebuild. |
| `promote_from_coverage.py` | Turns coverage findings into `recomp/symbols.toml` entries. |
| `interp_regions.py`, `lle_report.py`, `fn_info.py`, `exit_modes.py`, `jmptable.py`, `dis.py` | Reading aids: which stretches the interpreter still runs, which functions were refused and why, one routine's exits, a jump table, a disassembly. |
| `native_share.sh` | How much of the game's real work now runs as recompiled code (route run twice, all-interpreter vs normal). |
| `tier_check.sh`, `compare_tiers.py`, `logic_digest.py` | Proves recompiled code and the original code in the interpreter play the same game. |
| `check_baseline.sh`, `baseline/` | Re-checks the current build against the saved first recording (logic digests, plus per-frame hashes of the 6000-frame fight). |
| `contact_sheet.py` | Glues screenshots into one picture. |

## Checking against a trusted emulator, and re-recording
| File | What it does |
|---|---|
| `ref/` | A tiny runner for the Snes9x core plus compare/side-by-side scripts. Plays the same inputs in Snes9x and puts the pictures next to ours. See `ref/README.md`. |
| `record_baseline.sh` | Saves the latest `check_baseline.sh` runs as the new baseline. Only after a change that is meant to move timing or pictures, and after `tier_check.sh` and the Snes9x comparison pass. |
